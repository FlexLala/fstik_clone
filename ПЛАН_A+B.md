# Плагин «Не туда» — план

Два в одном: защита от отправки не тому + аналитика общения.
Обе части смотрят на одни данные (кто, кому, когда пишет), поэтому
это один плагин, а не свалка.

---

## Часть А: защита от отправки не туда (главное)

### Задача

Написал про начальника — отправил начальнику. Переслал переписку тому,
о ком переписка. Отменить нельзя: уведомление уже пришло.

### Как работает

Перехватываем сообщение **до** отправки, оцениваем риск, при высоком —
показываем подтверждение с крупным именем чата:

```
      Отправить в «Работа»?

  «да он вообще неадекват, задолбал»

  Причина: резкое слово в рабочем чате

     [Отмена]        [Отправить]
```

### Когда срабатывает

Не «всегда спрашивать» (такое выключают через день), а по правилам:

| Триггер | Пример |
|---|---|
| Помеченный чат | начальник, бывшая, рабочая группа |
| Мат/резкость в помеченном | другу — молчим, в работу — спросим |
| Пересылка | «пересылаешь переписку с Аней... Ане?» |
| Быстрое переключение | отправка через <3 сек после смены чата |
| Ночь | «3:00, точно отправляем?» |
| Молчаливый чат | длинный текст туда, где ты год молчал |

Каждое правило включается отдельно. Порог чувствительности — свой
для каждого чата.

### Технически

SDK даёт официальный хук, лезть в кишки не надо:

```python
def on_send_message_hook(self, account, params):
    # params.peer    — кому летит
    # params.message — что летит
    if risky:
        return HookResult(strategy=HookStrategy.CANCEL)
```

**Честный нюанс:** после отмены сообщение нужно отправить заново
своими руками (`send_message`). Для текста это надёжно. Для медиа и
ответов сложнее — надо аккуратно перенести поля `photo`, `document`,
`replyToMsg`. Начнём с текста, медиа проверим отдельно, и если будет
терять вложения — для медиа сделаем «предупредить, но не блокировать».

### Учится

Отменил отправку в чат — плагин это запомнил и в следующий раз
спросит увереннее. Наоборот: пять раз подтвердил — перестанет
доставать.

## Часть В: аналитика общения (второй экран)

Отдельная вкладка, чисто чтение базы, никаких хуков.

### 1. Висяки — кто ждёт ответа

```
Аня            2 дня    «Так что по субботе?»
Рабочий чат    5 часов  «Скинь отчёт»
```

Находит чаты, где последнее слово за собеседником и ты прочитал.
Умеет отличать «спасибо/ок/👍» — на такое ответ не нужен.

### 2. Дисбаланс

```
Аня      она за 4 мин    ты за 12 мин
Дима     он за 3 часа    ты за 2 мин   ← перекос
```

### 3. Охлаждение

```
Костя — было 40 сообщений в неделю, стало 3
```

### Технически

Всё в локальной базе, проверял:
```sql
messages_v2(mid, uid, date, data, out, read_state)
```
`out` = моё/чужое, `date` = когда. Из этих двух колонок считается всё.
Один SQL-запрос, без сети.

## Почему это не повторяет существующее

Проверил по каталогу из 357 плагинов:

| Похожий | Что он | Разница |
|---|---|---|
| TokenGuard | проверяет **что** шлёшь (токены) | не смотрит **кому** |
| UiTweaks | подтверждение на **всё** | задалбывает, у нас — умно |
| Remind | напоминалки, что **сам** создал | у нас находит само |
| Chat Stats | **сколько** сообщений | у нас **скорость** и долги |

Формулировки `не в тот чат`, `wrong recipient`, `без ответа`,
`висяк` — ноль совпадений по всему каталогу.

---

## Объём и план

~800–1000 строк, плюс тесты.

1. **Сначала часть А только для текста** — самое ценное, быстро
   проверишь на себе
2. Потом медиа и пересылки
3. Потом часть В (висяки, дисбаланс)

Так через день-два у тебя уже рабочая защита, а не «жди неделю».

## Что спросить у друга

1. Сработает ли идея вообще: **отменял бы он отправку**, если бы
   всплывало окно? Или это раздражает и он выключит на второй день?
2. Какие триггеры полезны, а какие лишние? (мат / ночь / пересылка /
   быстрое переключение)
3. Как лучше: **блокировать** с подтверждением или **задержка 5 секунд
   с кнопкой «Отменить»** — как отмена отправки в почте?

Третий вопрос важный. Второй вариант мягче: ничего не спрашивает,
просто даёт секунды передумать. Может, он вообще лучше.
